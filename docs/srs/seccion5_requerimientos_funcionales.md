# Sección 5: Requerimientos Funcionales (RF)

- **Must:** 6 requerimientos (50.0%) $\le 60\%$
- **Should:** 4 requerimientos (33.3%)
- **Could:** 2 requerimientos (16.7%)

---

## Tabla de Requerimientos Funcionales

| ID | Requerimiento | Prioridad | RN | Criterio de Aceptación |
| :--- | :--- | :--- | :--- | :--- |
| **RF-01** | El usuario puede visualizar en el mapa interactivo todas las locaciones históricas registradas mediante marcadores georreferenciados. | Must | RN-01 | **Caso correcto:** El mapa carga con éxito; se dibujan los marcadores en sus coordenadas exactas; al hacer clic en un marcador se despliega la ficha básica de la locación.<br>**Caso de error:** Falla la conexión con Google Maps; el sistema oculta el canvas del mapa y despliega la vista de catálogo alternativo en formato lista con todas las locaciones y sus coordenadas textuales. |
| **RF-02** | El usuario puede consultar el `Archivo` de una locación y examinar el listado de `Documentos` vinculados a ella. | Must | RN-01, RN-02 | **Caso correcto:** El usuario selecciona una locación existente; el sistema devuelve su descripción histórica y la galería de `Documentos` vinculados a su `Archivo`.<br>**Caso de error:** Se solicita una locación inexistente o inactiva por identificador; el sistema responde con error 404 informando que la locación no existe y redirige al mapa general. |
| **RF-03** | El usuario puede descargar un `Documento` en su formato digital original. | Must | RN-02 | **Caso correcto:** El usuario pulsa el botón de descarga sobre un `Documento` publicado válido; el navegador inicia la transferencia del binario correspondiente (`.jpg`, `.png`, `.webp`, `.pdf`) con su nombre original.<br>**Caso de error:** El recurso digital solicitado no se encuentra físicamente en el servidor de archivos; el sistema registra la anomalía y muestra el mensaje: *"El documento solicitado no está disponible temporalmente para descarga"*. |
| **RF-04** | El usuario puede enviar una propuesta de aporte ciudadano vinculada a una locación mediante un formulario público sin necesidad de autenticarse. | Must | RN-03 | **Caso correcto:** El usuario adjunta un archivo en formato admitido ($\le 25\text{ MB}$), selecciona una locación y proporciona una descripción; el sistema persiste la propuesta en estado `Pendiente` y muestra un mensaje de confirmación con su folio único.<br>**Caso de error:** El usuario intenta enviar el formulario sin adjuntar archivo o con un formato no permitido (`.exe`, `.zip`); el sistema bloquea el envío y muestra el mensaje de validación: *"Debe adjuntar un archivo válido (.jpg, .png, .webp, .pdf de hasta 25 MB)"*. |
| **RF-05** | El administrador puede autenticarse en el sistema mediante credenciales seguras para acceder al panel de administración. | Must | — | **Caso correcto:** El administrador ingresa usuario y contraseña válidos; el sistema valida la credencial y redirige a la consola de administración con sesión iniciada.<br>**Caso de error:** El administrador introduce credenciales incorrectas; el sistema deniega el acceso, incrementa el contador de intentos fallidos y muestra: *"Credenciales no válidas. Verifique sus datos"*. |
| **RF-06** | El administrador puede dictaminar el estado de una propuesta ciudadana a `Aprobada` o `Rechazada`. | Must | RN-03 | **Caso correcto (Aprobación):** El administrador selecciona una propuesta en estado `Revisada` y presiona aprobar; el sistema cambia el estado a `Aprobada`, genera automáticamente un nuevo registro de `Documento` público y lo incorpora al `Archivo` de la locación.<br>**Caso de error (Rechazo sin justificación):** El administrador presiona rechazar sin redactar motivo de rechazo; el sistema bloquea la acción indicando: *"Debe ingresar obligatoriamente una justificación para rechazar la propuesta"*. |
| **RF-07** | El usuario puede visualizar una línea del tiempo cronológica para locaciones cuyo `Archivo` cuente con múltiples `Documentos` fechados en distintos momentos. | Should | RN-04 | **Caso correcto:** El `Archivo` de la locación consultada cuenta con 2 o más `Documentos` con fechas distintas; el sistema renderiza el componente visual de línea del tiempo ordenado cronológicamente.<br>**Caso de error:** El `Archivo` de la locación tiene 0 o 1 `Documento`; el sistema oculta el botón de línea del tiempo y despliega la nota informativa: *"Esta locación aún no cuenta con suficientes documentos fechados para generar una cronología"*. |
| **RF-08** | El usuario puede descargar en un solo paquete comprimido (`.zip`) el `Archivo` completo de una locación. | Should | RN-05 | **Caso correcto:** El usuario solicita la descarga en lote del `Archivo` de una locación cuyos `Documentos` acumulados no superan los $100\text{ MB}$; el sistema compila el archivo comprimido `.zip` y transfiere la descarga.<br>**Caso de error:** El volumen acumulado de los `Documentos` de la locación supera los $100\text{ MB}$; el sistema rechaza la compresión al vuelo y muestra el aviso: *"El archivo de esta locación excede el límite de descarga en lote (100 MB). Realice descargas individuales"*. |
| **RF-09** | El administrador puede registrar una nueva locación geográfica en el sistema indicando su nombre, coordenadas y descripción. | Should | RN-01 | **Caso correcto:** El administrador ingresa nombre único, descripción y coordenadas latitud/longitud válidas; el sistema persiste la nueva locación y la refleja de inmediato en el mapa.<br>**Caso de error:** El administrador ingresa coordenadas fuera de rango geográfico permitido (ej. latitud $> 90$) o un nombre duplicado; el sistema rechaza el guardado y resalta los campos con error. |
| **RF-10** | El administrador puede registrar y publicar directamente un `Documento` asociándolo al `Archivo` de una locación existente. | Should | RN-02 | **Caso correcto:** El administrador carga un binario válido (`.jpg`, `.png`, `.webp`, `.pdf`), llena título, año, texto descriptivo y selecciona la locación destino; el sistema guarda el `Documento` en el `Archivo` con estado publicado.<br>**Caso de error:** El administrador omite seleccionar la locación asociada o el año de procedencia; el sistema impide la publicación y notifica los campos obligatorios pendientes. |
| **RF-11** | El usuario puede navegar entre `Documentos` y locaciones vinculadas temáticamente a través de hipervínculos internos. | Could | — | **Caso correcto:** El usuario hace clic en un hipervínculo embebido en el `Texto` de un `Documento`; el sistema actualiza la vista navegando directamente al `Documento` o locación referenciada.<br>**Caso de error:** El recurso destino del hipervínculo fue eliminado o despublicado; el sistema muestra el aviso: *"El recurso vinculado ya no se encuentra disponible"* y permanece en la vista actual. |
| **RF-12** | El usuario puede filtrar y buscar locaciones en el mapa mediante una barra de búsqueda por nombre o palabra clave de su reseña. | Could | RN-01 | **Caso correcto:** El usuario escribe un término (ej. *"Glorieta"*); el sistema filtra los marcadores visibles en el mapa mostrando únicamente las locaciones coincidentes.<br>**Caso de error:** No se encuentran coincidencias para el texto ingresado; el sistema mantiene los marcadores previos y muestra el mensaje flotante: *"No se encontraron locaciones que coincidan con la búsqueda"*. |
