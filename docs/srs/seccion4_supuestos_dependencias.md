# Sección 4: Supuestos y Dependencias

| ID | Tipo | Pregunta sin respuesta | Lo que se asume | Qué cambia si es falso |
| :--- | :--- | :--- | :--- | :--- |
| **SUP-01** | Supuesto | ¿Cómo se define la fecha de un archivo histórico cuando no se conoce el día exacto de la toma fotográfica o del documento? | Se asume que el sistema permite registrar fechas con precisión parcial: año exacto (ej. 1974), año y mes, o fecha completa (AAAA-MM-DD), ordenando cronológicamente por el primer día del periodo registrado. | Si se exigiera forzosamente fecha completa (día, mes y año), la clase `ArchivoHistorico` requeriría campos artificiales o valores por defecto que falsearían la precisión cronológica del acervo. |
| **SUP-02** | Supuesto | ¿Cuál es el tamaño máximo permitido para la subida de un archivo digital individual en una propuesta de usuario? | Se asume un límite máximo de subida de $25\text{ MB}$ por archivo individual aportado mediante el formulario público. | Si se permitieran archivos de mayor volumen (ej. escaneos TIFF de $200\text{ MB}$), se requeriría implementar carga por fragmentos (*chunked upload*), procesamiento asíncrono en segundo plano y mayor cuota de almacenamiento. |
| **SUP-03** | Supuesto | ¿Cuántos archivos históricos se espera que contenga una locación en la plataforma? | Se asume que una locación contiene entre 1 y 50 archivos vinculados. | Si una sola locación llegara a contener cientos o miles de archivos, la generación del archivo `.zip` al vuelo saturaría la memoria del servidor, obligando a implementar paginación profunda y generación asíncrona de descargas con notificación por correo. |
| **SUP-04** | Supuesto | ¿Qué ocurre con los archivos propuestos por usuarios cuando una propuesta es rechazada por el administrador? | Se asume que los archivos digitales asociados a una propuesta rechazada son eliminados del almacenamiento temporal en un lapso de 7 días naturales tras el dictamen. | Si debieran conservarse indefinidamente para auditoría histórica, se requeriría un submódulo de papelera/archivo histórico descartado con políticas de archivado a largo plazo. |
| **SUP-05** | Supuesto | ¿El administrador requiere jerarquías de permisos o roles diferenciados (ej. superadministrador, curador junior)? | Se asume que existe un único rol de Administrador con permisos totales de gestión de contenido y moderación de propuestas. | Si se necesitaran múltiples roles diferenciados con matriz de permisos granular (RBAC), se requeriría modelar clases como `Rol`, `Permiso` y flujos de aprobación escalonada. |
| **SUP-06** | Supuesto | ¿La vinculación de hipervínculos entre archivos y locaciones es manual o inferida automáticamente? | Se asume que la relación o mención de hipervínculos entre recursos es ingresada manualmente por el curador/administrador al redactar la ficha descriptiva. | Si tuviera que inferirse automáticamente, el sistema demandaría un motor de procesamiento de lenguaje natural (NLP) o reconocimiento de entidades nombradas (NER). |
| **DEP-01** | Dependencia | ¿Qué disponibilidad y límites operativos tiene el servicio de mapas externos? | Se asume que la API de Google Maps JavaScript tiene un nivel de servicio (SLA) de al menos 99.9% y cuenta con cuota de facturación mensual suficiente para el volumen de visitas. | Si la API agota su cuota o cae, el mapa no renderiza; se activa el modo degradado obligatorio mostrando la vista alternativa en catálogo/tabla cronológica. |
| **DEP-02** | Dependencia | ¿Dónde se conservan de forma persistente los binarios de los archivos multimedia (PDF, JPG)? | Se asume que el entorno del servidor web dispone de un volumen de almacenamiento de archivos persistente montado con permisos de lectura y escritura continuos. | Si el sistema de archivos del servidor fuera efímero (stateless sin volumen persistente), los archivos subidos por propuestas y curaduría se perderían ante cada reinicio del contenedor, requiriendo un servicio externo especializado de almacenamiento cloud. |
